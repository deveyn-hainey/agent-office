## Bus events the UI emits (additions)
* `routine:toggle {id, on}` — id ∈ `ambient | standups | daynight | camera`. `ambient` also calls `director.setAmbient(on)`.
  **Requests**: S3 may read `ctx.ui.routines.standups` / `.camera` (skip hourly standups / skip `camera` events when false); S1 may follow `daynight`.
* `ui:scenario {title}` (free play selected / scenario started), `ui:layout {}` (chat/drawers toggled), `projectmap:open` (anyone can emit it to open the map).
* The UI listens for `projectmap:open` and for `surface:click` on `board-4f` / `xray-2f` (two clicks <500 ms = double-click opens the map).

## Behaviours worth knowing
* Slack pane: channel `#pitchside` (or none) is shown in **#build-room**; unknown channel names get their own tab. `vote:locked` adds a "Decision log" line to #decisions. Reactions are cosmetic.
* UI sets `cam.setInsets` itself (measured from the DOM) and re-fits the current view when the free area changes — main.js's inset handler runs first, ours re-applies on the next tick.
* Binder: uses `director.getBinder(id)`; when it returns null the modal falls back to Jira cards + recent activity for that agent. (`data/binders.json` is currently 404 — S3's director fetches it; not a UI request.)
* CI toasts come from `surface:update` on a `ciwall` surface (`status` pass/fail); a director `toast` mentioning "CI" within 3 s of one is dropped to avoid doubles.
* Scenario picker maps keys `intake|review|full` via the alias map (`replay.load(key)`); `Free play` = `director.reset()` + ambient on. Unavailable scenarios show a toast.
* Stats (tasks/reviews/coffees/naps/minutes) are derived from bus events on top of a small deterministic baseline per agent.
* End-of-demo card shows on `replay:end`; "Findings caught" = findings on `screen-3f-a/b` (fallback: activity lines mentioning findings).
* Keys: 1–4 floors, A all, C clean, M map, S chat, `/` focus command box, Esc (summary → binder → map → drawers → desk → floor → clean), Space play/pause.
