## Contract: implemented as written (§6). Additions

### API additions on `agents`
| method | purpose |
|---|---|
| `snapshot(id)` / `snapshots()` | UI snapshot: `{id,name,short,role,color,seat,home,kind,floor,floorNo,slotId,visible,state,status,statusColor,activity,task,pose,alert,location,position,stats:{tasksDone,reviews,coffees,naps,chats,minutesWorking}}`. `state` = FSM state (below), `status` = contract status (`working/waiting/error/resting/finished`). `statusColor` already accounts for the "!" (yellow) and error (red). |
| `react(id, emoji, ms=2000)` | emoji reaction bubble (☕ 🎉 …). `say(id,'🎉')` also routes here automatically. |
| `carry(id, 'binder'\|'baton'\|null)` | agent carries a handoff binder / baton while walking & standing. |
| `setPose` extra poses | `talk`, `listen`, `vote`, `carry`, `stuck`, `sit` (in addition to the contract list). Poses without `ms` persist until the next `moveTo`/arrival. |
| `lookAt(id, target, {ms=6000})` | target also accepts a bare id, or `null` to clear. Heads turn first, body follows. |
| `pathTo(id, slotSpec)` | preview grid path. `debug()` returns nav blocked cells/paths; `showNavDebug(bool)` (also on with `?debug=1`). |

### FSM states (`snapshot.state`, event `agent:state`)
`hidden · idle · walking · at_desk · working · huddle · presenting · napping · needs_approval · thinking · stuck`.
`activity` is a ready-to-show string ("Typing in packages/odds/", "Grabbing a coffee", "Napping on the lobby sofa", "Riding the elevator to 3F" …). It is derived from status/task/slot/pose; to get "Typing in packages/odds/" the director just calls `setStatus(id,'working','packages/odds/')` (a task without spaces containing `/` or `.` is treated as a path; otherwise "Working on <task>").

### Extra bus events
* `agent:state {id, fsm, state, activity, statusColor, floor}` — emitted when FSM state / activity string / colour changes (≤ 4 Hz checks). The UI can subscribe instead of polling `snapshots()`.
* `agent:alert {id,on}` — when `setAlert` is called.
* `agent:alert-click {id}` — user clicked the yellow "!" badge. The same click also emits `agent:click {id, pick, via:'alert'}` so existing "open desk view" handling works; S4 may prefer `agent:alert-click` to jump to the Waiting-on-me card.
* `agent:status` payload also carries `fsm`.

### Behaviour notes
* `say()` durations: the bubble stays `max(ms, 1500 + 32*len)` ms (sim time, so pause/speed apply) so long lines are readable. Typewriter reveal ~60 chars/s. Under `clock.seeking` the text is shown fully at once.
* While an agent speaks, same-floor agents within 10 units turn their heads toward them and nod (listen); typing agents just glance.
* `ballot()` raises a YES/NO card in the right hand *and* pops the contract's ballot icon.
* Name tags (CSS2D pill with status dot) only show in floor/desk views (`cam:view`); bubbles always show.
* Agents on floors *above* the focused floor are hidden, mirroring the world's floor fading (listens to `world:floors` and `cam:view`).
* Moving to a slot held by another visible agent re-targets the nearest free slot of the same kind/room (so nobody shares a desk/sofa/seat). Reservations: `resolveSlot` reserves; arriving/moving releases the agent's other reservations.
* Doors: S2 calls `world.setDoor(name,true)` when an agent comes within 2 units of a gap and closes 1.5 s after the last agent leaves.
* Elevator follows §5.3 exactly (acquire → moveTo(from) → open → walk in → close → moveTo(to) with the agent following `carPos()` and fading to 30% → open → walk out → close fire-and-forget → release). If `world.elevator` is missing or throws, a fade-out/in hop is used. Stairs use `world.stairs.path(from,to)` per floor hop; `via:'auto'` picks stairs ~30% of the time for 1-floor hops.
* All awaits are cancellable (`stop`, a new `moveTo`, `reset`, `despawn`): the elevator lock is always released.

### Asks to other sessions (all optional; safe fallbacks are in place)
* **S1 (world):** the lying pose assumes sofa seat height ≈ 0.65 (hip ends ≈ 1.0 above the slot's floor); tweak `LIE_Y` in `js/agents/meeple.js` if sofas differ. Seated agents have hips ≈ 0.5 above the floor.
* **S4 (ui):** all bubble/tag CSS lives in a `<style id="s2-bubble-css">` injected by `js/agents/bubbles.js`; classes are `s2-*`. `css/base.css` `.bubble` is unused by S2.
* **S3 (director):** use `agents.carry(id,'binder')` for handoffs, `agents.react(id,'☕')` for ambient emotes, and `snapshot(id).activity` for activity lines if you want consistent wording.
