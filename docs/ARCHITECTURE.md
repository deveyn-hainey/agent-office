# Agent Office v2 — Architecture & Contracts

This is THE contract. Five engineers code against it blind. Where code and this doc disagree, the doc wins — tell S0.
Read `docs/BRIEF.md` first (product, style, roster, scenario beats). The v1 app lives untouched in `classic/`.

## 0. Conventions (read twice — most integration bugs come from here)

| Thing | Convention |
|---|---|
| Floors | Always a **0-based index**: `0 = 1F … 3 = 4F`. `floor` fields in JSON/APIs/events are indices. |
| Floor *numbers* | Only in human-facing strings: ids like `huddle-4f-2`, URL `view=floor:2` (= 2F = index 1), labels "2F". |
| Floor-local coords | Origin = floor centre, **+x right, +z toward the viewer, +y up**. Floor is 44 (x) × 28 (z): x ∈ [-22,22], z ∈ [-14,14]. The two **back walls** are at `z=-14` and `x=-22`. Floor `i` is lifted by `world.floorY(i) = i * 28` (= `floorPitch`). |
| Angles | Yaw radians. `0` faces **+z** (toward viewer), `π/2` faces **+x**, `π` faces **-z** (back wall), `-π/2` faces **-x**. Direction vector = `(sin a, cos a)` in (x,z). `facing` on slots and `rot` on furniture/surfaces use this. A surface's `rot` is the direction its **front face points**. |
| Rect/center | All `x,z,w,d` rects are **centre + size** (`w` along x, `d` along z). Furniture `rot` is a multiple of π/2; when `rot` is ±π/2, swap w/d for the footprint. |
| Time | `clock.t` = sim seconds. Scenario `t` = seconds on the scenario timeline (see §7). Clock-driven animation uses `dt` from `update(dt, simT)`; DOM timers use real time. UI clock text = real America/Denver. |
| Colors | Agent/status colors from `data/team.json` and `STATES` in `js/core/util.js`. Outline `#2b2622`, cream `#f4ecdc`. |
| Statuses | `working` · `waiting` (needs human, yellow) · `error` · `resting` · `finished`. (Not v1's `needs-you/stuck/idle`.) |
| Privacy | No network except three.js CDN + same-origin `data/*.json`. No real names/IDs/Slack text. Project "Pitchside", repo `acme/pitchside`, tickets `KAN-1xx`, PRs `#2xx`. |

## 2. Boot sequence & the `ctx` object

`js/main.js`: parse URL params → fetch `data/world.json`, `data/team.json` → `createScene` → `createWorld` → `createAgents` → `createDirector` → `createReplay` → `createUI` → wire picking → apply URL params → start.

```js
ctx = {
  bus,            // §3
  clock,          // §3
  params,         // parsed URL params (§10)
  data: { world, team },   // raw parsed JSON (read-only!)
  scene,          // core scene API (§4)
  cam,            // = scene.cam
  world,          // S1 API (§5)         — available to agents/director/ui constructors
  agents,         // S2 API (§6)         — available to director/ui constructors (NOT to createWorld)
  director,       // S3 API (§7)         — available to createUI
  replay,         // S3 API (§7)         — available to createUI
  ui,             // S4 API (§8)         — set after createUI returns
}
```
Construction order matters: inside `createWorld(ctx)` only `bus, clock, params, data, scene` exist. Inside `createAgents`: + `world`. Inside `createDirector`: + `agents`. Inside `createUI`: + `director, replay`. Anything needing a later module must look it up lazily (`ctx.agents` inside a function, not at construction). After boot, `window.office = { bus, clock, world, agents, director, replay, ui, cam, scene, ctx, params }`.

Modules register per-frame work with `ctx.scene.addUpdate((dt, simT, realDt) => …)` (returns an unsubscribe fn). `dt` is **sim** seconds (0 when paused, scaled by speed); use `realDt` for UI-ish things that should ignore pause.
Each module adds its own root `THREE.Group` to `ctx.scene.scene` (world → `world.group`, agents → `agents.group`). **Never** import three.js yourself: use `const { THREE, scene } = ctx.scene` (the import map makes `import * as THREE from 'three'` equivalent, but go through ctx for a single instance). Addons (`three/addons/...`) may be imported directly.

## 3. Core: bus, clock, util

### `ctx.bus` (`js/core/bus.js`)
```js
bus.on(name, fn)     -> off()      // fn(payload, name). name '*' = everything; 'agent:*' = prefix wildcard
bus.once(name, fn)   -> off()
bus.off(name, fn)
bus.emit(name, payload)            // handlers run synchronously; a throwing handler is logged, not propagated
```

### `ctx.clock` (`js/core/clock.js`)
```js
clock.t              // sim seconds since boot (monotonic, advanced by scene loop)
clock.speed          // 1 default;  clock.setSpeed(x)  (0.1–16)  emits 'clock:speed'
clock.paused         // clock.pause() / play() / toggle()        emits 'clock:pause' {paused}
clock.seeking        // TRUE while the director fast-forwards (see §7.4): snap, don't animate; resolve moves instantly
clock.simDate()      // Date = boot wall time + clock.t   (use for activity/slack timestamps -> consistent with replay)
clock.denver()       // real America/Denver now: {year,month,day,h,m,s,hours(float 0–24),ms}  (day/night lighting, wall clocks)
```
`js/core/clock.js` also exports `denverNow(date?)`.

### `js/core/util.js` exports
`TZ, STATES, PALETTE, OUTLINE, CREAM, hash, colorFor(agent), esc, truncate, clamp, lerp, easeInOut, angDiff, denverHM, denverHMS, denverFull, mmss, relative, parseParams, parseView`.
`parseView('floor:2') -> {type:'floor', floor:1}`; `'desk:codex' -> {type:'desk', agent:'codex'}`; `'all' -> {type:'all'}`.
`js/core/surfaceops.js` exports `applySurfaceOp(state, op, data)` — the single implementation of surface update semantics (§5.4).

## 4. Core scene & camera (`ctx.scene`, `ctx.cam`)

```js
scene = {
  THREE,                       // the three.js module namespace
  scene,                       // THREE.Scene (background cream)
  renderer, labelRenderer,     // WebGLRenderer, CSS2DRenderer
  camera,                      // THREE.OrthographicCamera (true isometric: azimuth 45°, elevation 35.264°, camera at +x,+z,+y)
  lights: { ambient, sun },    // base lights (S1 may tune intensity/colour/position for day-night)
  domElement, container,       // canvas, #stage
  floorY(i),                   // i*floorPitch
  addUpdate(fn) -> off,        // fn(dt, simT, realDt)
  pick(clientX, clientY, objects, recursive=true) -> {pick, hit, point:{x,y,z}} | null,
  css2d(domEl) -> CSS2DObject, // wrap a DOM element; add it to any Object3D as a label/bubble
  resize(), size:{w,h}, frames,
  cam,
}
```
**Picking:** put `object.userData.pick = { type, id, ...anything }` on the mesh/group you want clickable (`type` ∈ `'agent' | 'surface' | 'furniture' | 'room' | 'door'`). `pick()` walks up from the hit object to the first ancestor with `userData.pick`. Mark non-clickable decor/overlays `userData.noPick = true`. `main.js` calls `scene.pick` on click/hover over `[...agents.pickables(), ...world.pickables()]` and emits:
`pick:click {pick, point, clientX, clientY}` (pick null if nothing), plus a typed event `<type>:click {id, pick, point}` — i.e. `agent:click {id}`, `surface:click {id}`, `furniture:click`, `room:click`, `door:click` — and `pick:hover {pick|null, clientX, clientY}` (rAF-throttled; also sets the canvas cursor).
Drag-pan does not produce clicks (5px threshold). Raw canvas events are `scene:click` / `scene:hover` (consumed by main.js only).

### Camera API `cam` (a.k.a. `ctx.cam`, `scene.cam`)
```js
cam.setView(view, {animate=true, duration=0.9})   // view: 'all' | 'floor:2' | 'desk:codex' | {type:'all'} | {type:'floor',floor:idx} | {type:'desk',agent:id}
cam.getView()            // {type, floor?, agent?}
cam.nextFloor(±1)        // from 'all' enters floor view at the bottom (+1) / top (-1); clamps at ends
cam.setClean(bool) / cam.isClean()    // 'clean view': toggles class `clean` on <body>; css/base.css hides every .ui-region except #bottom-nav
cam.zoomBy(factor)       // >1 zooms in (user-style; cancels nothing)
cam.panBy(dxPx, dyPx)    // as if dragged
cam.setInsets({left,right,top,bottom})  // px of the viewport covered by UI; the 3D content is fitted/centred in the free area. main.js sets 260/300/50/80 on wide screens (0 in clean view / narrow). S4 may override.
cam.getInsets()
cam.setLocator(fn)       // fn(agentId) -> {x,y,z}|null world position for desk view (main.js wires agents.getWorldPosition)
cam.userActive(sec=15)   // true if the human wheel/dragged within `sec` seconds (the director must not hijack the camera then)
cam.viewH, cam.target    // read-only: visible world height, look-at point
```
Views: **all** = 4 stacked floors fitted (floorPitch 28 leaves interiors visible; upper slabs only clip the far-corner tip of the floor below); **floor n** = one floor fitted to the free area (dotted room annotations are shown only in this view — S1 listens to `cam:view`); **desk** = tight on one agent, follows it smoothly (right panel swaps to the agent's stats — S4 listens to `cam:view`). User wheel zoom / drag pan work in all views and keep the view type; any `setView` re-fits.
Honours `prefers-reduced-motion` (tweens become instant).

Events: `cam:view {view, prev}` (at start of the move), `cam:settled {view}` (tween finished), `cam:clean {on}`, `cam:zoom {viewH}`.

## 5. World (S1) — `createWorld(ctx) -> world`

Builds all four floors from `data/world.json` (§11): slabs with pastel accent walls on the two back walls, furniture, glass rooms, boards/screens (surfaces), elevator + stairs, dotted room annotations (visible in floor view), props, lighting from `clock.denver()`. Cutaway style: flat colours, thin `#2b2622` EdgesGeometry outlines, no front walls.

```js
world = {
  data,                     // = ctx.data.world
  group,                    // THREE.Group root (added to scene by createWorld)
  floorGroup(i),            // THREE.Group for floor i, positioned at y = floorY(i); everything inside is floor-local
  floorY(i), toWorld(floor, x, z, y=0) -> THREE.Vector3,
  slot(id)   -> {id,floor,kind,x,z,facing,room,seat?,lie?, wx,wy,wz} | null    // wx,wy,wz = world position (wy = floorY)
  slots(prefix?) -> slot[]  // all slots whose id starts with prefix (all if omitted)
  room(id) -> room | null,  rooms(floor?) -> room[]
  surface(id) -> {...def, state} | null
  surfaces: {
    list(floor?) -> id[],
    get(id) -> current state object,
    update(id, op, data) -> newState,    // applies applySurfaceOp, re-renders, emits 'surface:update'
  },
  setDoor(id, open) -> Promise<void>,    // glass-door swing; resolves when finished (instantly when clock.seeking). emits 'door:state'
  elevator: {
    acquire() -> Promise<release()>,     // exclusive use of the car; FIFO queue. Caller MUST call release().
    open(floor) -> Promise,              // car must already be at `floor` (or it is a no-op error-logged); doors open
    close(floor) -> Promise,
    moveTo(floor) -> Promise,            // car travels (speed in world.json), resolves on arrival; updates carPos()
    carPos() -> THREE.Vector3,           // world position of the car's standing spot (agents riding follow this)
    doorPos(floor) -> THREE.Vector3,     // world point just inside the doors on `floor`
  },
  stairs: { path(fromFloor, toFloor) -> THREE.Vector3[] },   // world-space zig-zag waypoints incl. both entry points (entry slot `stairs-<n>f` on each floor)
  fx(kind, floor, x, z),    // 'confetti' | 'steam' | 'puff' | 'sparkle' | 'ballot' ; unknown kinds ignored
  pickables() -> Object3D[],
  reset(),                  // clear surface states/doors/elevator to initial (called by director on replay reset)
}
```
S1 must make all slot positions in `world.json` visually correct (e.g. a `sofa` slot sits on a sofa; `desk` slot is a chair at a desk). If S1 needs to move furniture, it files a note (S0 regenerates `world.json`); S1 may add *decor* freely without touching data.

| `ciwall` | `{badge?:'local CI', status?:'idle'\|'running'\|'fail'\|'pass', jobs:[{name, status:'queued'\|'running'\|'pass'\|'fail'\|'warn', note?}]}` |

| `corkboard` | `{notes:[{text,x?,y?}], strings:[[i,j]]}` (indices into `notes`; red string) |

### 5.2 Doors
`walls[].gaps[].door` names a door (`door-3f-a`, `door-3f-b`). The glass room front wall has a gap; S1 renders a door leaf that swings via `setDoor`. **S2** opens a door as an agent approaches its gap (within ~1.5 units) and closes it ~1.5 s after passing; the director may also force it with a `door` event.

### 5.3 Elevator protocol (so S1 and S2 agree)
S2 does, per elevator trip `from → to`: walk to slot `elevator-<from>f` → `const release = await world.elevator.acquire()` → `await elevator.moveTo(from)` if the car is elsewhere → `await open(from)` → walk to `carPos()` → `await close(from)` → `await moveTo(to)` while the agent mesh follows `carPos()` → `await open(to)` → walk to `elevator-<to>f` → `await close(to)` → `release()`. With `clock.seeking`, S2 just teleports and never calls the elevator. Agents are inside the shaft (hidden behind the car walls / faded) while moving.

### 5.4 Surface updates
`world.surfaces.update(id, op, data)`; ops (implemented once in `core/surfaceops.js`):
`set` (replace state with `data`) · `merge` (shallow `{...state, ...data}`) · `clear` (`{}`) · `push` (`data:{path, item}` append to `state[path]`) · `update` (`data:{path, match:{k:v}, set:{…}}` patch matching items) · `remove` (`data:{path, match}`).
Emits `surface:update {id, kind, op, data, state}` **after** applying. S1 re-renders from `state`.

## 6. Agents (S2) — `createAgents(ctx) -> agents`

Meeple-like humanoids (rounded body + head, arms/legs, outline), colour from `team.json`. Pathfinding on a per-floor nav grid built by S2 from `world.json` (`nav.cell = 0.5`): blocked = `furniture[solid:true]` footprints (swap w/d for ±π/2 rot; `shape:'round'` uses `r`) + walls (thickness, **except `gaps`**) + the `elevator` and `stairs` rects + a 0.45 margin from the floor edge. Slots are always reachable (their cell is force-opened, as is the cell in front of door gaps). Walk with leg alternation + bob; sit/type at `desk` slots, lie on `sofa` slots (`lie:true`), sip coffee, etc. Multi-floor: elevator (§5.3) or stairs (`world.stairs.path`); choose stairs for short hops (±1 floor, ~30%) and elevator otherwise unless `opts.via` says otherwise. Agents with `startVisible:false` (reva, revb, scout) exist hidden until `spawn()`.

```js
agents = {
  group,                                         // THREE.Group root
  list() -> AgentView[],  get(id) -> AgentView|null
  // AgentView = {id,name,role,color,floor,slotId,status,task,visible,pose,home}   (floor/slotId = current/last arrived or destination while riding)

  moveTo(id, slotSpec, opts?) -> Promise<boolean>   // walk (and ride) to a slot; resolves true on arrival, false if cancelled/unreachable. opts:{run?:bool, via?:'auto'|'stairs'|'elevator'}
  teleport(id, slotSpec) -> void|Promise            // instant
  resolveSlot(spec, agentId) -> slotId|null         // 'slot:<id>' | '<id>' | 'free:<idPrefix>' (first slot with that prefix not reserved by another agent). Reserves it for agentId.
  occupant(slotId) -> agentId|null                  // reserved/occupied by
  isArrived(id) -> bool                             // false while walking/riding/waiting for the elevator. MUST be true immediately after moveTo when clock.seeking
  stop(id)                                          // cancel current move (agent stands where it is)

  say(id, text, {ms=3500, style='speech'})          // style: 'speech' | 'think' ("..." bubble, text ignored) | 'alert' (yellow "!") | 'cheer'
  clearBubble(id)
  setAlert(id, bool)                                // persistent yellow "!" above head (needs human approval)
  ballot(id, 'yes'|'no')                            // ballot icon pops above the head for ~2.5s
  lookAt(id, target)                                // heads/body turn: 'slot:<id>' | 'surface:<id>' | 'agent:<id>' | {floor,x,z}
  setPose(id, pose, {ms?})                          // 'stand' | 'sit-type' | 'nap' | 'cheer' | 'drink' | 'draw' | 'present' | 'wave' | 'think'; timed poses revert to the slot default
  setStatus(id, status, task='')                    // status ring/halo colour + AgentView.status/task; emits 'agent:status'
  spawn(id, slotSpec?) -> Promise                   // appear (puff fx) at slot (default home) and become visible
  despawn(id)
  getWorldPosition(id) -> THREE.Vector3|null        // current position (during rides: the car position)
  getFloor(id) -> idx
  pickables() -> Object3D[]                         // meshes carrying userData.pick={type:'agent',id}
  reset()                                           // all agents back to home slots, startVisible, status 'resting', no bubbles
}
```
Default behaviours (S2): arriving on a `desk` slot → `sit-type` if status `working`, otherwise sit idle; on `sofa` → `nap`; on `coffee` → `drink`; on `mural` → stand facing the wall; on `huddle`/`audience`/`conf-seat` → stand/sit facing `slot.facing`; on arrival face `slot.facing`. `clock.seeking`: every move teleports synchronously, bubbles/poses are applied in their final state, nothing awaits.
Events emitted by S2: `agent:arrive {id, slot, floor}` · `agent:depart {id, from, to}` · `agent:ride {id, mode:'elevator'|'stairs', from, to}` (from/to floor idx) · `agent:status {id, state, task}` (`state` ∈ STATES keys) · `agent:pose {id, pose}` · `agent:bubble {id, text, style}` · `agent:ballot {id, choice}`. (`agent:click` comes from main.js picking.)
Ambient wandering/coffee/naps are the **director's** job (it commands `moveTo`); S2 only ships the capabilities. S2 should expose an `agents.debug()` returning arrays of paths/blocked cells for screenshots if helpful (optional).

## 7. Director, scenarios, replay (S3)

`createDirector(ctx) -> director`, `createReplay(ctx) -> replay` (a transport facade over the director; `ctx.replay` is built after `ctx.director`).

```js
director = {
  load(idOrAlias) -> Promise<scenario|null>   // reads data/scenarios/index.json (aliases) + file; resets world/agents; emits 'replay:load'. Unknown id → console.warn, resolve null (never throw/404 spam: only fetch ids listed in index.json)
  reset()                                     // world.reset(), agents.reset(), cursor=0; emits 'replay:reset'

  setAmbient(bool), claim(ids), release(ids), isClaimed(id)   // ambient office life drives unclaimed agents only
  command(text, {from='You'}) -> Promise<{ok, summary}>       // free-text command box (§7.6)

replay = { load(id), play(), pause(), toggle(), seek(t), setSpeed(x), time, duration, playing, scenario, list() -> Promise<[{id,title,file}]> }
```
`replay:*` transport state is broadcast on the bus so the UI never polls (below).

### 7.1 Scenario JSON (`data/scenarios/<id>.json`; listed in `data/scenarios/index.json`)
```jsonc
{
  "id": "intake-huddle", "title": "…", "summary": "…", "version": 1,
  "agents": ["lead","codex"],                 // claimed (kept out of ambient) while the scenario runs
  "chapters": [{ "t": 0, "label": "Request lands" }],   // shown as markers on the scrubber
  "events": [ { "t": 12, "type": "move", "agent": "codex", "to": "slot:huddle-4f-2" }, … ]
}
```
`data/scenarios/index.json`: `{"scenarios":[{"id","title","file"}], "aliases":{"intake":"intake-huddle","review":"hero-review","full":"full-day"}}` (S3 owns it and adds `hero-review.json`, `full-day.json`).

### 7.2 Timeline & waiting (the async-move rule)
* `t` = scenario seconds from start. Events execute in order of `t` (stable for ties) when the **scenario cursor** reaches them. The cursor advances with sim `dt`, **except while blocked** by a wait event.
* `move` is **non-blocking**: it starts the walk and the next events fire on schedule. To sequence on arrival, insert `{"type":"waitArrive","agents":[…]|"all","timeout":60}`: the cursor stops at that event's `t` until every listed agent `isArrived()` (or `timeout` sim-seconds pass), then continues; later events keep their authored `t` values, i.e. they run *relative to the wait's end* (the timeline "compresses" around the wait). The scrubber therefore shows scenario time, not wall time.
* `{"type":"waitAnswer","id":"ask-1","timeout":120}` blocks until that ask is answered (or times out → auto-resolves with first option... or the event is simply skipped: S3's choice, document in notes).
* Under `clock.seeking`, waits never block (agents teleport).

### 7.3 Event types (all have `t` and `type`; unknown keys ignored)
| type | fields | semantics |
|---|---|---|
| `status` | `agent, state, task?` | `agents.setStatus`; activity line |
| `say` | `agent, text, ms?=3500, style?='speech'` ; `quiet?:true` suppresses the auto activity line | `agents.say`; adds `activity` (kind `say`). `style:"think"` → "…" bubble (text ignored). `style:"alert"` → "!" |
| `move` | `agent, to, run?` | `to`: `"slot:<id>"` (exact) or `"free:<idPrefix>"` (first free slot with that prefix, e.g. `free:huddle-4f`, `free:sofa-1f`, `free:hot-1f`). Claims the agent. |
| `waitArrive` | `agents|"all", timeout?` | see §7.2 |
| `waitAnswer` | `id, timeout?` | see §7.2 |
| `look` | `agents:[…]` (or `agent`), `at` | `agents.lookAt` (`"surface:board-4f"`, `"agent:lead"`, `"slot:…"`) |
| `pose` | `agent, pose, ms?` | `agents.setPose` (e.g. `cheer`, `draw`, `present`, `nap`) |
| `surface` | `surface, op, data` | `world.surfaces.update(surface, op, data)` — ops/shapes in §5.1/§5.4 |
| `feed` | `channel?, who, text` | emits `slack:message` (S1's Slack TV and S4's pane show it) |
| `vote` | `agent, proposal:"D-14", choice` | `agents.ballot`, emits `vote:cast`, **auto-tallies** the matching proposal on `vote-4f` (yes/no counts, `votes{}`); when 2 votes agree the proposal gets `locked:true` and `vote:locked {proposal,text}` is emitted. Activity line. |
| `ask` | `agent, id, text, options?=["Approve","Skip"]` | status `waiting`, yellow "!" (`setAlert`), emits `ask:open {id,agent,text,options}`; activity (kind `ask`) |

### 7.4 Seeking (`?seek=60`, scrubber)
`director.seek(t)`: emit `replay:seek {t}` → `reset()` (emits `replay:reset`) → set `clock.seeking=true` → run the event loop in 0.1 s steps until the cursor reaches `t` (waits do not block; moves teleport synchronously) → `clock.seeking=false` → emit `replay:seeked {t}`. **All modules** must treat `clock.seeking` as "apply final state now". On `replay:reset` the UI clears its logs/slack/asks and S1/S2 return to initial state.

### 7.5 Ambient life (S3)
When not claimed/scripted, the director runs ambient behaviours through the public APIs: coffee runs (`free:coffee-1f`), water-cooler chats with short banter (`cooler-1f-1/2`), idle agents nap on `free:sofa-1f` then grab `free:hot-1f` desks, wander (`wander-*`), monitor flicker is S1's own. `setAmbient(false)` / `?ambient=0` disables it.

### 7.6 Command box
`director.command(text)`: emits `command:submitted {text}` → adds the request to the whiteboard (`board-4f` `requests`) and Slack as "You" (`slack:message {you:true}`) → heads turn (`look` at board) → resolves intent (verb/agent/place parsing: "tell Muse to draw the bet365 logo on the lobby wall", "send Codex to conference room B", "huddle everyone", "Grok take a nap", "Argon present findings", "review PR 212") → agent walks and acts (mural gets a **generic placeholder badge with the typed words**, never trademark art) → emits `command:result {text, ok, summary}`; returns the same. Unknown intents: lead says "I didn't catch that", `ok:false`.

### 7.7 `data/binders.json`
`{ "<agentId>": { "summary": "…", "sections": [{ "title": "Active tasks", "items": ["KAN-143 Theme tokens", …] }, { "title": "Handoffs", "items": ["HANDOFF-2026-11-02.md …"] }] } }` — fictional. S4 renders it in the binder modal / desk panel via `director.getBinder(id)`.
